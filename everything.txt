1. THE PROBLEM
   - Scientific literature is full of "compound figures": single image files that contain multiple sub-plots (charts, graphs, photos, diagrams).
   - Downstream tasks like "Chart Question Answering" or "Image Classification" fail on these composites. They need atomic images.
   - Existing solutions focus heavily on medical imagery (ImageCLEF).
   - General domain solution is missing.
   - Challenge: The variety is huge (Bar charts mixed with microscopic images mixed with flowcharts).

2. PROJECT GOALS (ASSIGNMENT 1)
   - "Bring Your Own Data" (BYOD): Create a novel dataset because none exists.
   - Train a Baseline: Use YOLOv11 (state-of-the-art detector) to solve the task.
   - Deliverables: Dataset, Model Weights, Demo App, Report.

3. DATA ENGINEERING PIPELINE (THE CORE INNOVATION)
   This project is 80% Data Engineering.

   Phase A: Real-World Extraction (The "SCI-3000" Source)
   - Source: PDFs from the SCI-3000 dataset.
   - Tool: `SCI3000Extractor.py` (Custom PDF miner).
   - Output: Thousands of raw images.
   - Curation: Manually graded ~2,500 images.
     - "Atomic" (Single): 1,160 images. Used as seeds for synthesis.
     - "Compound" (Real): 700 images. The "Gold Standard" for testing.

   Phase B: The "Real" Dataset Construction
   - Tool: Label Studio (Local instance).
   - Task: Manually draw bounding boxes on 700 real compound figures.
   - Tags: `Chart`, `Illustration`, `Image`, `Table`, `Text`, `Subpanel`, `Shared X-Axis`, `Shared Y-Axis`, `Shared Legend`, `Shared Title`.
   - Result: High-quality, difficult, real-world interactions.

   Phase C: Synthetic Augmentation (Solving Scarcity)
   1. The Stitcher (`SCI3000SyntheticCompoundStitcher.py`)
      - Methodology: Take the 1,160 real "Atomic" images.
      - Logic: Randomly sample 2-8 of them.
      - Layout: Arrange them in grids (1x2, 2x1, 2x2, 3x2, etc.).
      - Augmentation: Add padding, background noise, random "A)", "B)" subpanel labels.
      - Output: 10,000 "Fake" compound figures with PERFECT labels (since we know where we pasted them).
      - Benefit: Massive volume for training the "concept" of separation.

   2. The Plot Generator (`CompoundPlotGenerator.py`)
      - Methodology: Use Matplotlib to draw pure vector-based charts.
      - Types: Line, Scatter, Bar, Hist, Boxplot.
      - Configuration (`CompoundPlotConfig.py`):
        - 2,500 images.
        - Layout Probabilities: Favors 2x2 (22%) and 1x3 (20%).
        - Axis Sharing: 45% of plots share ticks (only outer axes labeled). This teaches the model to infer implicit axes.
        - Global Elements: 75% Global Title, 55% Global Legend.
      - Benefit: Teaches the model fine-grained details like "Shared Legend" or "X-Axis label" positions.

   Phase D: Assembly & Splitting (`03_Dataset_Assembly.ipynb`)
   - Strategy: Stratified Shuffle Split.
   - Why? We need to ensure that rare classes (like `Table`) appear in validation and test sets.
   - The "Injection" Trick: Real tables were rare. We injected 50 synthetic tables into Val and Test sets to ensure we can calculate an mAP score for them.
   - Oversampling: The training set is heavily oversampled with synthetic data to prevent betting on the "majority class".

4. DATASET VARIANTS (THE "PRODUCTS")
   The pipeline produces three distinct datasets for different users:

   Dataset 04: `04_all_classes` (The "Kitchen Sink")
   - Classes: All 11 labels.
   - Use case: Research / Debugging.
   - Metrics: Hard to get high mAP because "Text" or "Subpanel" are ambiguous.

   Dataset 05: `05_selected_classes` (The "Production Product")
   - Classes: `Chart`, `Illustration`, `Image`, `Table`.
   - Use case: Actual application. "Give me the sub-figures".
   - Performance: Best results (mAP ~0.58).
   - This is what the Demo App uses by default.

   Dataset 06: `06_compound_chart_splitter` (The "Analyst")
   - Classes: `X-Axis`, `Y-Axis`, `Legend`, `Title`, `Subpanel`.
   - Use case: "I have a chart, now extract the variables".
   - Training: Trained on the Matplotlib synthetic data primarily.

5. MODELLING & OPTIMIZATION (ASSIGNMENT 2)
   - Framework: Ultralytics YOLOv11.
   - Evolution:
     1. Baseline: YOLOv11 Nano @ 640px. Fast but missed small axis text.
     2. Scaling Up: YOLOv11 Small @ 640px. Better capacity, still resolution limited.
     3. Resolution Hack: YOLOv11 Small @ 960px.
        - Why? Scientific figures often have tiny text for "Shared Axis". At 640px, these are ~4 pixels tall. At 960px, they are readable features.
        - Result: Significant jump in mAP.
   - Final Stats:
     - Training Time: ~1.7 hours on RTX 3090 (40 epochs).
     - Batch Size: 16 (limited by VRAM at 960px/1280px).
     - Optimizer: AdamW (Default is good).
     - Loss: Box Loss + CLS Loss + DFL Loss.

6. REPOSITORY STRUCTURE & TOOLS
   - `src/`: Source code.
   - `models/`: Where weights live (`.pt` and `.yaml`).
   - `dataset/`: Where data lives.
   - `runs/`: Output of YOLO training.

   Utilities (The "Glue"):
   - `download_dataset.py`: Handles Hugging Face authentication and download + unzipping.
   - `download_models.py`: Similar, but for weights. Supports arguments (`all`, `model_name`).
   - `upload_data.py`: Custom script to zip folders (HF has a file limit per folder) and upload them.
   - `relativizeSplitPaths.py` / `absolutizeSplitPaths.py`:
     - The "Path Problem": YOLO hardcodes absolute paths in `.txt` files.
     - Solution: Before upload, make relative. After download (in `prepare.py`), make absolute.

7. DEMO APPLICATION (ASSIGNMENT 3)
   - Stack: Streamlit.
   - Features:
     - Auto-download: If you pick a model you don't have, it fetches it.
     - Interactive Threshold: Slider for Confidence IoU.
     - Side-by-Side: Original Image vs Inference.
     - Ground Truth Overlay: If the image is from the test set (has a .txt label file), it draws green boxes on the original image for comparison.
     - "Demo Assets": A folder `docs/assets` with cool examples to try immediately.
